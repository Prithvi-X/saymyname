# Documentation and traceability

- Link each implementation task to a stable requirement, feature, API/data, test or change-request ID.
- Do not rename or rewrite approved source documents to make the code fit. Raise a conflict and obtain a decision.
- Record material technical trade-offs as ADRs with context, options, consequences, owner and approval.
- Update traceability, relevant documents, tests and release notes when an approved behaviour or interface changes.
- Preserve the document version and decision history. Do not silently defer committed P0/P1 scope.
- Distinguish observed facts, assumptions, recommendations and approved decisions in reports.
